## Summary

**Problem ([006 implementation notes](./006_Highlighting-Basics.md)):** On **paginated** Android EPUB, highlight **create** and **edit** are painful: selection handles **flash/jump**, dragging toward the **page edge** risks **unwanted page turns**, and users **over-highlight**. App-side mitigations (decoration latch, `ReaderSurface` memo, progress pause during selection, full-bleed chrome) did **not** fix dogfood for Nefko. Upstream issues exist (Readium [kotlin-toolkit #746](https://github.com/readium/kotlin-toolkit/issues/746), Chromium).

**Rejected prior experiment:** Default **`scroll: true`** for all reading was **reverted** — that is a **core reading IA** change, not an approved fix for highlight pain.

**This ticket:** Spike and, if the gate passes, ship a **scoped** interaction: **while the user is creating or adjusting a highlight**, temporarily switch the navigator to **vertical scroll**; when the session ends, restore **pagination**.

**Hypothesis:** Continuous scroll during **selection adjustment only** makes handle drag predictable without abandoning paginated reading for normal page turns.

**Not a schema or BookQuote API change.** Locator + snippet contract from 006 stays identical.

---

## Product flow (target UX)

Applies to **create** (new selection → Highlight action) and **edit** (tap existing decoration → adjust → Highlight to update same `quote_id`).

| Step | User | System |
|------|------|--------|
| 1 | Long-press / select text (or activates existing highlight for edit) | Selection becomes active (`onSelectionChange` with locator). |
| 2 | — | Enter **`highlightAdjustmentSession`**: merge **scroll-on** into `ReadiumView` `preferences` (keep font tier from 005). Optional subtle banner (reuse or extend edit banner). |
| 3 | Drag selection handles up/down along the passage | Scroll layout; **no** paginated “corner drag” to change pages. |
| 4 | Tap **Highlight** in selection actions | Save or update `BookQuote` (existing 006 path). |
| 5 | Selection dismissed (tap away, clear selection, or post-save) | Exit session → **pagination** preferences restored. |
| 6 | **Cancel** (edit banner) | Clear `editingQuoteId`, dismiss selection if possible, exit session → pagination. |

**Reading between highlights:** Default experience remains **paginated** (swipe turns). User does **not** toggle scroll in settings in this ticket.

**Progress:** Keep 002 debounced writes **paused while selection active** (`textSelectionActiveRef` pattern in `ReaderScreen`). Revisit only if scroll-mode emits noisy `onLocationChange` during handle drag.

## Decisions (lock before implementation)

| Topic | Decision |
|-------|----------|
| **Scope** | Temporary scroll **only** during an active highlight adjustment session — not a user-facing “reading mode” setting. |
| **Default reading mode** | **Pagination** when not in a highlight session (unchanged). |
| **Trigger** | **Any** active text selection enters scroll (`SelectionEvent.locator` present). **Edit:** scroll also on when `editingQuoteId` is set (tap existing decoration) even before a new selection. **Locked** ([Nefko Q3](#clarifications-for-nefko)). |
| **End session** | Selection cleared **or** successful Highlight save **or** Cancel edit **or** leaving reader screen (flush state on unmount). |
| **Preferences merge** | **`services/reader/`** builds `preferences` passed to `ReaderSurface`: `{ ...fontSizeFrom005, scroll: true }` only in session. Single object per render — no feature-layer Readium imports. |
| **Locator discipline** | Still store **Readium locator JSON** only; no scroll offset in SQLite. |
| **Ship bar** | Step 0 **gate** must pass on **physical Android** before merging product behavior. If gate fails, ticket closes with **Implementation notes** only (no half-shipped toggle). |
| **Toolkit** | Record `react-native-readium` version + Readium native versions in notes. Optional **version bump** is in scope for the spike if release notes suggest selection fixes — separate commit/section in notes. |

## Step 0 — Technical gate (block implementation until answered)

Run on **physical Android**, imported EPUB preferred (same as 006 acceptance).

1. **Runtime toggle:** With book open in **pagination**, user selects text → app sets `scroll: true` in `preferences` → selection **still visible** and handles **draggable** without remount glitch.
2. **Restore:** Clear selection → `scroll: false` (or omit scroll) → **pagination** returns; **same logical place** (locator stable within tolerance; no chapter jump).
3. **Save path:** In scroll session, create highlight → `snippet` + `locator_json` in data page; decoration renders after reload.
4. **Edit path:** Activate decoration → session → adjust → Highlight → **same `quote_id`**, updated snippet/locator.
5. **Handle quality:** Subjective vs 006 baseline: **less jitter**, easier multi-line range — record pass/fail and short video note if possible.
6. **Regression:** 005 font tier change with quotes present still acceptable; 002 resume after back → reopen.

**Gate outcomes**

| Result | Action |
|--------|--------|
| **Pass** | Proceed to Steps A–C (minimal product wiring). |
| **Fail** (selection lost, position jump, worse jitter) | **Do not ship** hot-swap. Document failure modes; keep pagination-only; track upstream / optional future “always scroll” **setting** as separate ticket. |

## Proposed steps (after Step 0 pass)

### Step A — Session state in `services/reader/`

- Add focused module(s), e.g. `useHighlightAdjustmentSession` (or extend `useReaderBookQuotes` only if it stays under ~150–200 lines — otherwise split).
- Inputs: `onSelectionChange`, `editingQuoteId`, save/cancel callbacks.
- Outputs: `highlightSessionActive`, merged `readerPreferences` for `ReaderSurface`.
- Preserve 006 rule: **avoid re-rendering `ReaderSurface` on every selection micro-event** except when **toggling scroll** (unavoidable preference change). Document tradeoff in implementation notes.

### Step B — Wire `ReaderScreen`

- Combine `useReaderFontSize().preferences` with session overlay before passing to `ReaderSurface`.
- Extend banner for **create** flow if edit-only banner is insufficient.
- Ensure `cancelHighlightEdit` ends session and restores pagination.

### Step C — Device acceptance

- Repeat **006 acceptance spike** scenarios with focus on **multi-line** and **paragraph-crossing** selections.
- Record comparison: paginated-only (main branch) vs hot-swap (branch).
- Nefko sign-off before commit.

### Step D — Docs

- Short note in [Architecture](../01_PRD-and-Guidelines/3_Architecture-and-Dependencies.md): “highlight adjustment session” and pagination default (if product ships).
- Append **006** implementation notes with link to **006.1** outcome (pass/fail).

## Design philosophy

**Consistent with [Design Philosophy](../01_PRD-and-Guidelines/2_Design-Philosophy.md)**

- Logic in **`services/reader/`**; thin `ReaderScreen`.
- Small modules; split if hook grows past guideline size.
- Locator-based persistence unchanged ([Schema and paths](../01_PRD-and-Guidelines/4_Schema-and-Paths.md)).

**Consistent with [BookQuotes](../01_PRD-and-Guidelines/6_BookQuotes.md)**

- Highlight still created/updated via same `BookQuote` row semantics.

**Inconsistent / intentional product delta**

- **Temporary** layout mode change during highlight — a **core interaction** change, but **narrower** than global scroll default. Requires this ticket’s acceptance and banner/feedback so users are not surprised by reflow during adjustment.

**Rollback strategy**

- Baseline **006** on `main`/GitHub. Work on a branch; merge only after Step 0 + Step C. If merged behavior regresses, revert the 006.1 commit(s) — no DB migration to undo.

## Risks

| Risk | Mitigation |
|------|------------|
| `preferences` change **remounts** navigator and **drops** selection | Step 0; if unsolvable, fail gate |
| Reflow **disorients** user when entering scroll | Anchor on selection locator; optional `goTo` after toggle if Readium API allows |
| **Worse** jitter in scroll than pagination | Fail gate; document; do not ship |
| Extra `ReaderSurface` re-renders when session toggles | Accept for toggle only; keep `onSelectionChange` on ref pattern otherwise |
| Chapter / spine boundary selections | Explicit acceptance case in Step C |

## Clarifications for Nefko

*Question 1:*
If Step 0 passes technically but scroll feels **disorienting** in dogfood, should we ship behind a **hidden dev flag** first, or hold until copy/UX polish in a follow-up?
*Answer:*
We won't ship until it feels good, but we will first implement the hot swap (if janky) and then we'll refine the UX after we know that it worksin a clunky way. 

*Question 2:*
Should **create** (new highlight) use the **same banner** as edit (“Adjust the selection…”), or **no banner** for create and rely on system selection chrome only?
*Answer:*
use the same banner. It should be there for create - we do not want to rely on system selection chrome. THe way it works now is good, no need to change this part. 

*Question 3:*
Is **any** active text selection enough to enter scroll session, or do you want session **only** after the user taps an **existing** highlight to edit (narrower blast radius)?
*Answer:*
It must be **any**. THe bug persists whenever there is a highlight (whether it i a new creation or an existing one). It needs to work for both.

## Implementation notes

**2026-11-19 — scroll-only dogfood:** Flicker **does not** reproduce with global `scroll: true` (Nefko, physical Android).

**2026-11-19 — hot-swap wiring:** Removed global scroll spike. `useHighlightAdjustmentSession` + `mergeReaderViewPreferences` in `services/reader/`; `ReaderScreen` merges font prefs with `scroll: highlightAdjustmentActive`. Banner when session active (create + edit).

**2026-11-19 — selection lost on scroll toggle:** Readium clears selection when `preferences.scroll` changes after select. Post-select hot-swap **rejected** for create UX.

**2026-11-19 — pre-select arm (dogfood):** `HighlightAdjustmentGestureShell` — `LongPressGestureHandler` + `NativeViewGestureHandler` (120ms) arms scroll before WebView selection. Avoids Reanimated/Worklets (broke Android CMake). Root `GestureHandlerRootView`.

**2026-11-19 — Android `libworklets.so` missing:** Expo 57 / `expo-router` pull `react-native-worklets` + Reanimated transitively; `expo-modules-core` links worklets when installed. Stale `android/.cxx` dirs reference old CMake hashes. **Fix:** direct dep `react-native-worklets` (`expo install`); wipe `.cxx` under `react-native-worklets`, `react-native-reanimated`, `expo-modules-core`, `android/app`; then `npx expo run:android` (one Gradle graph).

**App modules:** `highlightAdjustmentPreferences.ts`, `useHighlightAdjustmentSession.ts`.
