## Chapter 5.3 — Glossary and further reading

### Key vocabulary

This chapter is the book's vocabulary in one place, so it introduces nothing new. Each entry below gives a short definition and the chapter where the term was introduced, which is the best place to return to if the definition is not enough. The terms are arranged alphabetically, and where a term has a symbol or code formatting in the text, it is sorted by its letters.

### Glossary

**Adapter.** A service that wraps an outside library so the rest of the app talks to a stable, app-specific interface. In the Reader, the reader adapter is the only code that knows about Readium. (Chapters 2.3 and 3.3)

**APK.** Short for Android Package, the single file that contains an installed Android app: its compiled code, assets, manifest, native libraries, and JavaScript bundle. It is a ZIP archive with a different extension. (Chapters 1.1 and 2.2)

**Book record.** The app's entry saying that a title is in the library, holding its metadata, its `bookId`, and its relationship to a file. (Chapter 4.1)

**`bookId`.** The app's own stable identifier for a book, used to link the file, the book record, and every user artifact. (Chapter 4.1)

**Bridge.** The boundary across which the JavaScript layer and the native layer exchange messages. The word is used loosely in this book to cover how React Native connects the two. (Chapter 1.2)

**CFI.** Canonical Fragment Identifier, epub's standard string for pointing to an exact spot in a book's content. In the Reader it appears inside a Readium locator and is not a separate system. (Chapter 3.4)

**Companion file.** An auxiliary file, such as notes or a guide, attached to a book. A future feature, and not part of the first phase. (Chapter 5.2)

**Component.** A reusable piece of interface, written as a function, that returns a description of what should appear on screen. (Chapter 1.2)

**Config plugin.** A small piece of code that edits the generated native projects to add settings or libraries, so that native configuration is repeatable and not hand-edited. (Chapter 2.1)

**Content URI.** The address Android's file picker hands to an app, which grants access to a file without revealing a dependable path to it. (Chapter 4.1)

**`compileSdkVersion`.** The version of Android's programming interfaces that the code is compiled against. It must be new enough for every library the project uses. (Chapter 2.2)

**Debounce.** Delaying an action until a burst of triggers has stopped, so that it runs once instead of many times. The Reader uses it to save reading position. (Chapter 4.2)

**Decoupling.** Arranging code so that one part can change without forcing changes in another. (Chapter 3.3)

**Dedupe.** Short for deduplication, the detection of a file the library already holds. Not yet built. (Chapter 5.2)

**Design tokens.** Named values for colors, spacing, and typography that the interface uses in place of raw numbers and hex codes. (Chapter 2.3)

**Dev client.** A custom version of the app, built for the team, that loads JavaScript from the developer's computer while including whatever native code the project needs. It replaces Expo Go once Readium is in the stack. (Chapter 2.1)

**Drizzle.** A library that describes the database schema in TypeScript and produces typed queries and migrations. (Chapter 4.2)

**EAS.** Expo Application Services, Expo's cloud service for building and distributing apps. (Chapters 2.1 and 5.2)

**Epub.** The open file format for reflowable digital books: a ZIP archive containing an OPF package file and XHTML content. (Chapter 3.1)

**Expo.** A toolkit built on React Native that supplies project setup, a development workflow, ready-made native modules, and optional cloud builds. (Chapter 2.1)

**expo-sqlite.** Expo's library for using SQLite from a React Native app. (Chapter 4.2)

**Feature.** A product area, such as the library or the reader, whose screens and supporting code are kept together in one folder. (Chapter 2.3)

**`fileOnDevice`.** A field on the book record saying whether the epub file is currently stored on the phone. (Chapter 4.1)

**Flow.** The full path of one user action through the layers of the app. (Chapter 5.1)

**`goTo`.** The adapter's verb for moving the reader to a given location, such as a saved position or a table-of-contents entry. (Chapter 3.3)

**Gradle.** The build system that assembles the project's code, assets, and libraries into an APK. (Chapter 2.2)

**Hook.** A function, usually beginning with `use`, that lets a component read or manage state and behavior without containing that logic itself. (Chapter 2.3)

**`href`.** The path of one content file within a book. It forms the first part of every locator. (Chapters 3.2 and 3.4)

**JavaScript layer.** The part of the app written in JavaScript or TypeScript, where most of the team's code lives. (Chapter 1.1)

**JSX.** The syntax that lets a description of the interface look like HTML tags inside JavaScript or TypeScript. (Chapter 1.2)

**Keystore.** A file that holds the cryptographic key used to sign an app. (Chapter 2.2)

**Local-first.** An approach in which data lives on the user's device as the primary copy, and any server or cloud service is optional. (Chapter 1.1)

**Locator.** Readium's structured description of a place in a publication. **Locator JSON** is that description written as text so it can be stored. (Chapters 3.2 and 3.4)

**Managed workflow.** The way of using Expo in which the native Android and iOS folders are generated from configuration instead of being edited by hand. (Chapter 2.1)

**Metro.** The program that gathers an app's JavaScript into a bundle and serves it to the app during development. (Chapter 1.2)

**Migration.** A versioned, recorded change to a database schema, applied in order so that every copy of the database reaches the same structure. (Chapter 4.2)

**`minSdkVersion`.** The oldest version of Android on which the app agrees to be installed. (Chapter 2.2)

**Native layer.** The part of the app written in the phone's own languages and frameworks, where heavy work such as drawing book pages happens. (Chapter 1.1)

**Navigator.** In Readium, the component that displays a publication and responds to page turns, selection, and settings. (Chapter 3.2)

**NCX and nav document.** The two formats epub uses for a table of contents: NCX in Epub 2, and an XHTML nav document in Epub 3. (Chapter 3.1)

**OPF.** The Open Packaging Format file, the book's master document, listing its metadata, files, and reading order. (Chapter 3.1)

**Prebuild.** The step that generates the native projects from the project's configuration and config plugins. (Chapter 2.1)

**Progression.** A number between zero and one saying how far through a content file, or the whole book, a position lies. (Chapter 3.4)

**Props.** The inputs a component receives from whoever uses it. (Chapter 1.2)

**Publication.** Readium's name for a book once it has been opened and understood. The **publication lifecycle** is the sequence it passes through: not opened, opening, ready, and closed. (Chapters 3.2 and 3.3)

**Reflow.** The re-laying out of text that happens when font, size, or margins change. (Chapters 3.1 and 3.4)

**Reflowable.** Describes a book whose text the reading app breaks into lines and pages, in contrast to a fixed-layout book. (Chapter 3.1)

**Route.** The named location that navigation code uses to find and show a screen. (Chapter 1.2)

**Sandbox.** The private area of storage Android assigns to each app, which other apps cannot normally read. (Chapters 3.1 and 4.1)

**Schema.** The definition of a database's tables and columns. (Chapter 4.2)

**Screen.** A full-page view in the app, such as the library or the reader. (Chapter 1.2)

**SDK.** Software development kit, the collection of libraries, tools, and platform files that development for a platform requires. (Chapter 2.2)

**Service.** Non-visual code that does a job for the rest of the app, such as importing a file or talking to the epub engine. (Chapter 2.3)

**Snippet.** A short piece of plain text saved with a highlight so the app can show or search it without opening the book. (Chapter 3.4)

**Spine.** The ordered list inside the OPF that says which content files make up the book and in what sequence a reader moves through them. (Chapter 3.1)

**SQLite.** A small, self-contained database engine that stores an entire database in a single file and runs inside the app. (Chapter 4.2)

**Stack.** The set of technologies layered together to produce a working product. (Chapter 1.1)

**State.** Information a component remembers and can change over time. (Chapter 1.2)

**`targetSdkVersion`.** The version of Android the app has been written and tested against, which tells the system which behaviors to apply. (Chapter 2.2)

**User artifact.** Anything the reader creates or accumulates while reading, such as a position, a highlight, or a note. (Chapter 4.1)

**XHTML.** A strict version of HTML that follows the rules of XML, and the format of an epub's content files. (Chapter 3.1)

### Further reading

A book of this length can only introduce its subjects, and each technology in the stack has documentation that goes much further. The sources below are the ones to reach for first. All of them are maintained by the projects themselves, which makes them more reliable than most third-party tutorials, though also more likely to change, so check the version the Reader uses before following any guide to the letter.

For the app's foundations, the [React Native documentation](https://reactnative.dev/docs/getting-started) explains components, layout, and the differences from the web in depth, and the [Expo documentation](https://docs.expo.dev) covers the development workflow, development builds, config plugins, prebuild, and EAS. The Expo pages on development builds are the most useful companion to Chapter 2.1, and the pages on `expo-document-picker` and `expo-file-system` match the import flow in Chapter 5.1.

For Android builds, the [Android developer documentation](https://developer.android.com/guide) is the authority on SDK versions, signing, and scoped storage, and the sections on app signing and on data and file storage match Chapters 2.2 and 4.1.

For epubs, the [W3C EPUB specification](https://www.w3.org/TR/epub-33/) is the formal definition of the format. It is long and written for implementers of the standard, so it is best used as a reference when a particular question arises, such as how the spine or the navigation document is meant to work, and not read from the beginning.

For the reading engine, the [Readium project site](https://readium.org) describes the toolkit, its architecture, and the locator model that Chapter 3.4 depends on. The [`react-native-readium` repository](https://github.com/5-stones/react-native-readium) is the library the Reader uses, and its README, issues, and example app are the best guide to its current props, callbacks, and known problems.

For data, the [SQLite documentation](https://sqlite.org/docs.html) explains the database itself, the [expo-sqlite reference](https://docs.expo.dev/versions/latest/sdk/sqlite/) covers the Expo binding, and the [Drizzle documentation](https://orm.drizzle.team) covers schemas, queries, and migrations.

### Common pitfalls and gotchas

The first pitfall with reference material is version drift. Expo, React Native, Readium, and `react-native-readium` change on their own schedules, and the architecture document notes that their versions are coupled. A tutorial written a year ago may describe a setup that no longer works. When documentation and the project disagree, trust the project's own installed versions and the current documentation for exactly those versions.

The second is treating the glossary as a substitute for the chapters. A definition of a locator or a migration tells a reader what the word refers to, and it cannot tell them why the project is arranged around it. When a term in this list is unclear in practice, the chapter named beside it is the better source.

The third is reading the specifications first. The epub standard and the Readium documentation are precise and thorough, and for a newcomer they are also dense. Starting from a working example, such as the example app in the `react-native-readium` repository, and consulting the specification to answer specific questions, is a far gentler path.

The last is forgetting that the glossary will age with the book. Terms will be added as the project grows, particularly when the features listed in Chapter 5.2 are built, and names mentioned here as illustrative, such as the adapter's `EpubSession`, may change in the code. The code and the project's own documents are the final authority, and this book is a guide to understanding them.
