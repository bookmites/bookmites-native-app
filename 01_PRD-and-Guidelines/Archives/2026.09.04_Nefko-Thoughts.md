I think that what it is is an eReading app with a built in AI chatbot. You can start a chat from a highlight, or just open the chat. The bot has the context for where you are in the book (can read the chapter, maybe, or the pages before and after). The app lets you pull from our library or upload your own epubs.

So nothing too original or crazy there, but I do think that it would be really a wonderful thing. The core principles are:

- Users own everything: the epub files, their metadata, etc... It is all local (but we make it easy for them to back things up on their own infra). Advanced users plug in their own API keys for models (but we might have to help out other types of users).
- Very transparent: We want people to use AI, but we make it metaphorical, not a black magic box. Users can see memories, see skills, see personality files, etc...
- Everything is open source. obviously.
- Transparent composability. Over time, especially on the AI infra stuff, make it to where people can add to our library.

The real interesting things get into the ways we architect things. All of this is up for debate, but some early thoughts:

**Book detail files:** I think it is good to have a file that has some details about how the author says things. For example, I’m reading “Revolt of the Masses” right now by Ortega, and he means something very specific when he says “minorities”—he is using the word in a different way than we use it in the US today. We’d want to make sure that the bot knows this. If Ortega defines “minorities” in Chapter 1, but we’re reading Chapter 5 and he uses the word, the bot needs to have that in context. I think that that could be done with a little metadata file, a ‘companion file’ that operates as a skill file for the book. Another one that comes to mind is that in Dostoyesky novels, lots of times he uses different names for the same characters and people find that confusing. A little name mapper might be useful for those readers. We can make these files transparent to users. People could publish these companion files for others to use. We don’t take on the burden of creating them for every book, but we can create the app that makes them easy to make and plug in. It is also a subtle teaching moment for users about the capabilities of bots and the way we use context. We could make these companion files visible and available when someone gets an ebook from our library, and we could also have them available in a searchable way in our library, so when someone opens their own epub in the app, they can search our library to see if there are any helpful companion files.

**User Data:** We’ll need to store user data somewhere. Data about their place in the book, highlights, notes, bot conversations and memories, etc... We could probably store that locally on device, then have them back it up to iCloud/Google Drive.

**Users sharing their data:** we DO want to understand how people are using the app so we can improve it. Most FOSS has terrible usability for a reason. However, we’ll only want them to opt-in to sharing things with us, and we want to be very transparent to them in the interface about what they’re sharing. I have thoughts on how to do this well.

**Bots (models).** I think over time there is a two-level approach to this. (1) For advanced users who will go get their own API keys, we’ll have a simple way for them to plug that in. (2) For those who don’t, I think we should consider a pay-per-use model where we handle the models and pass those costs through to them with a very transparent pricing model (I wouldn’t be opposed to charging a bit of a tax on model usage here if it was modest). I think that (1) is easier than (2), so it is the place to start. However, I know that most of our target market isn’t going to be able to figure out their own API keys, so we’ll probably need (2) to really accomplish our mission.

**Bots (personalities & skills).** I think that we should have a modular, personality-driven approach to bots. In the beginning, we’ll probably have our own soul file / skill set for our bot (and probably only one). Like everything else, we should make it very transparent to users (though the UI) how the bot “works”. Where the personality comes from, where the ‘skills’ come from. What ‘memories’ it is saving about the user, etc... maybe in the beginning the user can’t edit everything, but we should make memory editable from the beginning. Over time, we can expand the app so that others can load in personalities, etc...
